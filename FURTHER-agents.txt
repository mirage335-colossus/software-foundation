Optional follow-ups
==================

Optional improvements for later work; these are not pending qualification or
authorization to execute. Reuse existing mechanisms and preserve their safeguards.

- Publication-only reuse of qualified CI artifacts, binding original consumer
  evidence and exact bytes without rebuilding or relaying through a workstation.
- Authenticated assembly/retry reuse of successful producers with unchanged inputs,
  preserving original attempts and complete required inventories.
- Earlier native platform diagnostics for affected contracts before costly dependent
  builds, while retaining required final qualification.
- Compact evidence reporting that distinguishes execution, retention, qualification
  and publication and links the original receipts.
- Conservative development-check selection if measurements justify it, retaining
  broad coverage for unknown dependencies and shared build changes.
- Thin agent-operation wrappers if necessary to remove repeated bookkeeping while
  preserving ownership checks, supervised completion and failure handling.

2026-10-05 review: existing same-job assembly/publication already avoids a full
candidate relay, and authenticated certification retries already reuse successful
whole batches. Extending either to older application producers or publication-only
adoption needs new source/configuration/provider and consumer-evidence binding.
Keep those extensions optional; this iteration preserves the established release
path. Existing preflight dependencies, final evidence summaries and checked agent
helpers remain preferable to duplicate diagnostics/reporting/bookkeeping layers.


Test parallelism follow-ups (separate discussion)
-----------------------------------------------

- Implemented: automatic test/planner/tooling workers use CPU/RAM capacity,
  preserving affinity/container limits, explicit overrides, CPU/RAM headroom,
  shared-resource locks and the complete inventory. Parallel parents scope nested
  worker allowances instead of letting each child claim the entire machine.

- Parallelize the slow Python suites with isolated worker processes, using existing
  timing receipts to select useful partitions rather than spawning a process for
  every small test. Extend tools/run_tests.py and the existing inventory/aggregation
  mechanisms while preserving module/class fixture semantics, per-case results and
  explicit platform exclusions. Reject missing, duplicate, skipped or failed cases;
  retain bounded execution, descendant cleanup and complete diagnostic evidence.
  Deferred after measuring five slow suites: the two dominant suites spend 92%
  and 97% in one class; balanced suites offer about three seconds of theoretical
  class-level savings. Existing whole-suite scheduling remains the useful first
  step. Module fixture registration was repaired and regression-tested separately.

- Implemented: independent Linux source/recovery/archive/ABI batch cases share
  verified read-only inputs and prepared images, with private writable outputs,
  containers, temporary resources and displays. Output handoff requires confirmed
  container shutdown; all failures aggregate. Native Windows/host-browser and
  package-manager operations remain ordered. Source/recovery evidence stays separate.


Release discovery resilience (implemented)
-----------------------------------------

- Initial GitHub release discovery now handles the narrow case where concurrent publication
  shifts pagination: retry a repeated release ID across distinct response pages,
  after validating the records. Reuse tools/github_release.py transport machinery
  with one shared attempt, time and API-request budget across transport and
  inventory retries; do not nest independent retry loops. Explicitly bound extra
  full-inventory reads and their request cost. Restart the complete inventory and
  discard every prior page; never silently deduplicate or accept partial results.
  Persistent repeated IDs must fail with useful diagnostics. Malformed records,
  authentication/permission failures and genuinely ambiguous matching tags must
  remain errors, without gaining retries from this change. Preserve existing API
  savings, shared discovery and all source, asset, digest and signature checks.
  Recovery stays read-only: never repeat a mutation because discovery failed or
  infer absence from an unsuccessful read. Add focused tests for a repeated ID
  followed by success, persistent repetition, exhausted shared budgets, discarded
  partial results and unchanged publication safeguards. Assert zero extra API calls
  or waits on successful first-attempt discovery and bounded request counts on
  failures. Exact-ID final publication/native-acceptance readback was implemented
  in c45f8f3; that fix is retained.
