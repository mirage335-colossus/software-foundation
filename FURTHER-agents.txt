Further improvements to this example
===================================

Keep only improvements that would substantially improve this example as a starting
point after accounting for complexity, maintenance and fragility. Reducing GitHub
Actions time to qualified binary releases is a high priority. Possible usefulness
only to a derived project, hypothetical growth or marginal savings is insufficient.
Entries are proposals, not pending qualification or authorization to execute.

- Shorten recovery from failed or interrupted releases by extending the existing
  GitHub Actions retry path to reuse successful cloud application producer outputs.
  Avoid repeating expensive successful builds when their source, configuration,
  provider and dependency inputs are demonstrably unchanged. Preserve authenticated
  original producer attempts, exact bytes, complete inventories and consumer
  evidence; rerun affected checks and every remaining required release gate.
  Reuse the existing cloud assembly/publication path, without workstation payload
  relays or a separate publication system. Missing or incompatible evidence must
  require rebuilding or requalification, never weaker acceptance.
