# Native rich4083 source candidate

This is a separate native CPU WebCore/JSC document, physical-input, editor and
document-actions source recipe. It preserves the pixel1795 recipe byte-for-byte.
The shared Publisher additionally selects the reviewed bounded-public-text and
stable Begin-selection successor. Its origin record retains the frozen capsule
preimage while `after_sha256` and the adaptation record identify the current
source. Truncated TUI projections are capability/lease-free; the complete public
and private Begin baseline remains exact except for its verified postfocus text
range. The old pixel recipe and historical actions maps are unchanged.
These helpers have pure fixture evidence, not actual native WebCore compilation
or runtime evidence.

It supplies source and bounded component checks; it supplies no actual native
dependency/toolchain baseline, engine/provider DSO, retained SDK or eligible
runtime/release proof. The actual WebCore binding and richer native APIs remain
uncompiled against the real engine. Source inspection and fake callbacks cannot
qualify a native engine.

The provider is explicitly profile kind 4, capabilities 4083, with composite
contract `33e23c8972497a64956a765b24a61538fe1cfcabe6be80af8e19ceb0e401e221`.
One engine, Page, Session, Publisher and native editor composition serve both
terminal document facts and generic bitmap output. GUI backend selection does
not choose a different implementation of the page. Public C table layouts and
all old profile selectors/validators remain unchanged. The external consumers
select the new typed actions facts through their independent admission route.

EventHandler.h enters the compile roots. Historical ignored paths in provenance

There are 157 mapped source files, including 48 engine leaves. The graph has 32
direct provider TUs. It selects the shared document/form/resource/service code,
physical provider, raw-key dispatch/mapping, input codec, native editor backend
and wire adapter, editor codecs, document action codec and the shared UI/popup/
internal-clipboard owners. The legacy Controller.cpp,
copied-Wasm host/dispatch/record/shim, JavaScript glue, browser media bridge and

The actual WebCore target privately includes the document-provider parent and

enabled only for the explicit23 source family; PopupOwner is the only newly

flags remain unchanged. The complete graph requires the real selected WebCore,

the inherited physical 2 descriptor, editor descriptor and all five actions pins.
The existing three-phase body dispatch/readback/passive completion and ACK debt
rules remain shared native code. Runtime application/worker IDs are fresh,
monotonic and nonzero; metadata never supplies them.

The hidden native ensure helper uses the reviewed NativeProviderOnce controller.
The first eligible getter chooses its immutable binding thread. Wrong major,
null output, short capacity and maximum minor below 1 reject before registration.
Concurrent/reentrant binding returns REENTRANT without waiting; a ready getter
from another thread returns WRONG_THREAD. Registration publishes State/owner or
sticky failure with release/acquire ordering and contains exceptions. It invokes
no Host, Page, VM, author/resource lookup, START or DSO constructor. Inert
preflight rejects a foreign-thread START before permanent retention/commitment.

There is no raw registration entry or caller-selectable profile bypass.

## Windows and remaining qualification

The source target policy admits Linux x86_64/aarch64 and Windows x86_64 only,
with 64-bit little-endian layouts and exact R/B/actual compile-target joins. The
Windows branch requires clang-cl, the separately verified static CRT/toolset/SDK
and native dependency inventory, explicit DirectWrite/font policy and its native
target identity. Missing prerequisites fail concretely. Windows metadata may be
generated on a qualified POSIX producer; that is not Windows executable support.

The Windows private-component export policy covers static engine components,
LLInt extractors/object library and provider, with only the getter exported.
A `.def` alone does not hide upstream dllexport directives. DirectWrite's dynamic
font resolver uses the reviewed private system-only policy. Actual PE/ELF imports,
exports, CPU/runtime floor, DLL isolation, product fonts/data/notices and
clean-machine execution still require independent evidence. Engine C++23 and its
declared Windows policy do not raise ordinary Foundation C++20 support promises.

The source, inert CMake and pure metadata tests do not compile WebCore. The
separate opt-in bootstrap CLI compiles only actual Guard/Once and ordinary codecs
with fake callbacks, plus a generated native64 header, bounded to 90 seconds and
two jobs. Its default unittest registration is source-only. Such component
passes do not establish connected native HTML, bitmap/TUI behavior or eligible
retained groups. Actual engine configure/build/link/runtime and complete platform
qualification need separately costed, authorized native maintenance inputs.

Ordinary web resources and C/C++/Rust portable modules continue through the
[retained-kernel payload tools](../../docs/appended-applications.md). Neither
payload iteration authorizes an engine/kernel build, even a cache-hit build.
Missing retained input reports maintenance needs instead of rebuilding.


## Shared UI and internal clipboard source

The recipe selects the same UI registry, popup owner/controller and internal
rich-clipboard store as browser physical/editor. Their four direct TUs compile
once per provider artifact. Five selected WebCore overlays supply HTML select,
EmptyClients, Editor, DataTransfer and PasteboardEmscripten integration; they are
WebCore owners, not duplicate provider TUs. Original engine headers and frozen
capsule/supplier maps retain their exact authority; new provenance records keep
the real supplier CPP preimages and explicit reviewed successor origin.

Private callback resolution requires one actual in-tree, non-imported STATIC
WebCore target linked into this provider. The recipe rejects shared, module,
interface or imported WebCore targets; it does not add hidden cross-DSO exports
or rebuild incompatible engine inputs. The existing PIC gate still applies.

UI/clipboard ownership lasts for one process. Document/service invalidations
retire document authority; facade/driver close does not synchronously tear down,
reset or rebind the clipboard owner. The clipboard is internal, with no host OS
clipboard dependency or backend-specific feature behavior. Component fixtures
and source metadata do not establish actual WebCore parsing, native linking,
popup/clipboard runtime or retained native reuse eligibility.
