# Retained document-provider source recipe

This recipe selects the document-v2 pixel (`1795`), physical (`2003`) or
editor-v1 (`2035`) provider explicitly. It preserves the base provider header and C table layout:
Provider ABI 1.1 adds the document extension; Host ABI remains 1.0. It does not
enable a provider, create an eligible retained group or qualify a binary.

`source/` contains the 83 selected text files from the frozen
`0002-document-raster` source capsule. `overlays/physical/` contains the 26
changed or additional files needed by the frozen 98-file
`0003-document-physical` capsule. Each `source-imports-*.json` names every
selected logical path, exact tracked file, byte hash, size, mode and origin.
The modern shared facts header is an explicit physical-capsule override for
the pixel and physical selections. `overlays/editor/` selects the CPP-only
`0005-cpp-only-outcome` successor. Its 158 import records retain 109 of the 118
capsule leaves and explicitly override the historical metadata template with
the single production adapter, the shared Publisher, and seven call-site leaves
with explicitly reviewed source successors. The new shared UI overlay adds ten
private helper/header leaves, five engine CPP leaves and four owner wrappers.
The immutable118-file capsule and its raw source map remain provenance.
The two original core headers are not source postimages; their exact original
bytes and physical aliases remain required by the reuse proof. These imports preserve the capsule source files rather than
silently repairing their historical metadata generator.

The raw source maps in `provenance/` preserve the original source-capsule
maps, including historical path labels. They are provenance, not input-path
authority. `source-projection-*.json` binds each selected retained path to its
exact baseline preimage and successor bytes. The source assembler does not
infer aliases from filenames or equal hashes. The two declared source-header
alias pairs are reviewed layout choices and make no historical inode claim.
Actual original physical aliases require separate copy-receipt evidence.

The shared Publisher has an explicit source successor in all three selections.
Its current origin hashes the joined bounded public-text and Begin-selection
fixes; `supersedes` keeps the exact historical capsule origin. Long public Text
nodes publish a scalar-safe bounded preorder prefix. Truncated projections grant
no form capabilities or leases and omit selection; deferred public body-pool
exhaustion stages a coherent empty truncated body/forms pair. Malformed retained
text and private baselines remain strict. Begin alone may accept a stable native
postfocus text range after a second passive same-control sample, with every other
public/private baseline still exact. These C++ changes passed extracted-helper
and source checks; their real WebCore compilation/runtime remain unverified.
Raw source maps, original projection preimages and old compiled candidates keep
their original identities. The next retained source group must start from the
separately pinned original copied-browser baseline, as the assembler requires.

The new `runtime/generate_document_metadata.py` is the single production
metadata adapter. It generates the exact document Build contract, an explicit
compiled profile and the bounded24-field pixel,30-field physical or38-field
editor facts. The editor selection uses the existing pure editor contract
helper, its distinct13-field Build/configuration/provider contract, and the
explicit `DocumentCopiedProfile::editor` value3. It never infers an upgrade
from capability bits.
The retained shim includes `BibCopiedDocumentMetadata.generated.h`; the
maintenance graph produces that filename in `document-generated/`.
`prelink-plan.json` binds the source-only configuration without a circular
recipe/build/header digest. Generation does not establish runtime evidence.

## Source preparation

`assemble_sources.py plan` verifies a separately pinned original copied-browser
source group, the maintained imports, all original input bytes and the selected
projection. It does not discover SDK tools, extract archives or launch programs.
`assemble` additionally copies the complete source group into a new caller-owned
directory and seals its new recipe and inventory only after the source and output
checks succeed. The qualified filesystem adapter is currently POSIX only.

```sh
python3 recipes/webkitwasm-document-v2/assemble_sources.py plan \
  --baseline-sources /absolute/retained/copied-browser-sources \
  --baseline-recipe-sha256 ORIGINAL_RECIPE_SHA256 \
  --baseline-sources-sha256 ORIGINAL_SOURCES_SHA256 \
  --document-profile pixel
```

Use `assemble` with the same arguments and an explicit new
`--output /absolute/owned/document-sources` to save the source group. This can
read and copy large original supplier archives; the pure fixture tests do not
perform that operation. Independent source and inventory pins are mandatory.
The resulting group keeps the original target, paired SDK identity, complete
supplier archives, ordered supplier patches and every original license input.
It also keeps the exact original recipe and inventory as predecessor provenance.

The original supplier patch and selected notice index are referenced by exact
hash in the source imports. Their maintained homes are
[`../webkitwasm-copied259-v1/source/wrapper/src/patches/webkit-emscripten.patch`](../webkitwasm-copied259-v1/source/wrapper/src/patches/webkit-emscripten.patch)
and [`../webkitwasm-copied259-v1/notices/INDEX.json`](../webkitwasm-copied259-v1/notices/INDEX.json).
The selected notices are checked against their retained originals; the full
baseline notice set remains present. Existing source copyright and license
headers are preserved. These references do not replace the full supplier license
and distribution obligations in the retained source group.

## Incremental producer boundary

The explicit maintenance profiles select 23 direct translation units and six
existing engine owners for pixel, or31 direct units and14 owners for physical. Editor selects35 direct
units and16 exact original engine owners; it adds the native backend, wire
adapter, deep binary codec and UTF16/LF projection, never the legacy Controller.cpp.
All three preserve the five original ordered archives (2,076 members total); only the
selected owner positions are replaced. That leaves2,070,2,062 or2,060 original archive members available for
reuse, respectively. The profiles record exact donor command identities,
ordered include paths, definitions and explicit exception policy. Equal source
bytes never establish object reuse.

`tools/appended_engine_document_maintenance.py` admits only a new document reuse
proof with explicit context authority, an original header-identity sidecar and
the exact source projection. Complete original contexts remain an accepted mode.
The separate selected-and-opaque mode binds full source/include/config/SDK
contexts for the six,14 or16 recompiled engine owners. Newly compiled direct
units use the exact profile-approved donor arguments and bounded deltas. The
remaining original archive slots are trusted opaque artifacts, joined by exact
ordered member tuples and command hashes to the independently pinned original
baseline proof, build receipt, target and paired SDK. This mode does not invent
unrecorded historical primary-source hashes or ordered unified bodies. Its
`include-search-v1` mode preserves the complete original namespace, rejects new
files shadowing old compiler roots and forbids changed core headers or config.
The current selections change only the explicitly identified C++ owners.
Historical header aliases and every changed alias postimage must be bound to the
original copy receipt; arbitrary VFS overlays and basename deduplication are not
accepted. The legacy copied259 reuse proof is not a document proof.

Physical original preimages in that sidecar and logical predecessor preimages
in the source projection are distinct authorities: both must retain their exact
hashes. New metadata is staged under `metadata/document-v2/`, including the
byte-exact predecessor proof. This directory stays outside the original quoted
include namespace. Posthoc source observations remain explicitly labeled; they
do not upgrade the old build receipt or establish new runtime evidence.

`prepare_reuse.py plan|prepare` produces the new proof metadata from separately
pinned original proof, source recipe and inventory, SDK manifest, projection and
selected source-authority records. Every path/pin pair is explicit. The authority
records bind the selected original unified include order and physical source
mapping; absent records cause a concrete prerequisite report. Reading an SDK
manifest does not verify or discover the SDK tree. The helper reads named metadata
only, with 64 MiB per-document and 256 MiB total input/output budgets. It launches
no tools and copies no original source, object, archive or SDK files.

`prepare` additionally requires a new `--output` directory. Its `metadata-root/`
contains the new proof and sidecars; `ASSEMBLY.json` outside that root is written
last and labels the result as an incomplete metadata fragment. The exact original
retained files must be independently materialized before the complete maintenance
driver can admit the new root. The helper cannot mutate the old proof, treat its
fragment as a complete inventory or fall back to a cold build.

An actual admitted plan, selected compilation, five archive
updates, final link, Worker bootstrap and same-run provider/consumer evidence
remain separate work. No source fixture, generated header or candidate build
is runtime eligibility. The physical selection is not editor/IME support;
the proposed editor profile requires its own frozen protocol and source recipe.

Focused source fixtures are in
`tests/test_appended_engine_document_sources.py`, metadata fixtures in
`tests/test_appended_engine_document_metadata.py`, and planner fixtures in
`tests/test_appended_engine_document_maintenance.py`. Metadata-fragment fixtures
are in `tests/test_appended_engine_document_reuse.py`. They use inert inputs and
make no engine, SDK or browser execution claim. The supported build entry point
and manual qualification policy still govern actual maintenance.

## Explicit editor source selection

Use `--document-profile editor` with the source assembler and reuse metadata
preparer to select the new source inputs. The maintenance selection JSON uses
`document_profile: "editor"` and the exact editor maintenance profile. The
public pixel/physical contract selector remains closed to editor; the internal
producer chooses the separate pure editor helper explicitly. Old generated
pixel/physical header spelling and facts/configuration semantics are preserved;
the shared adapter's changed bytes create truthful new recipe identities.
Historical source groups and their evidence are never relabeled.

The editor profile requires `BIB_ENGINE_PROVIDER_EDITOR_V1=1` in addition to
document-v2 and selects only the editor facts/configure exports. It retains
query3/form6/ACK7 and adds query4/editor8/9 through the distinct private editor
table. Editor replies and commands are bounded to1MiB; query4 is bounded to236
bytes. The metadata generator requires the exact editor header, contract,
catalog and binary schema plus the existing physical/document interfaces.
Pixel/physical reject those editor-only metadata arguments.

The added original owners are `UnifiedSource-be65d27a-9.cpp` (Element.cpp,
WebCore ordinal602) and `UnifiedSource-767013ce-4.cpp` (EventHandler.cpp,
ordinal721), with all eight original siblings in their exact order. The
unchanged core headers remain Element.h SHA256
`34f6ee2561154aab969512785d98c9834069dac201f7ed1ec11297297cc7a8c5`
and EventHandler.h SHA256
`9b1611b0fdfc0bbea951e08a2b15ed873939015325612c87bc9383de19793786`.
CPP-only private free-function observation scopes preserve the original public
and private member declarations and instrument one actual native dispatch. No
ODR/header compatibility waiver, synthetic native API or historical depfile
claim is admitted. A fresh exact original-source-authority/reuse fragment must
bind these owners before a later actual producer plan can be admitted.

Source/metadata fixtures are not an actual SDK, native/WebCore parser, object,
link, runtime or connected HTML TUI result. The recipe supplies source
prerequisites. Body link/button/focus/selection intent transport, a composed
single-select runtime and live same-identity observation still require actual
engine evidence. The reviewed shared popup/clipboard implementation below is
source, not a connected runtime pass. A source selector cannot stand
in for those behaviors or satisfy release qualification.

## Shared rich UI source successor

Physical/editor select identical shared UI, popup and internal rich-clipboard
bodies under `overlays/ui/`; native4083 selects those same C++ bodies in its own
recipe. Compile UiOwner, PopupOwner, NativePopupController and BibClipboardStore
once each. Only PopupOwner adds local exceptions. The five additional WebCore
replacements are HTMLSelectElement, EmptyClients, Editor, DataTransfer and the
standalone PasteboardEmscripten owner; four exact unified wrappers retain every
original sibling. Private free-function hooks preserve all original core headers,
class layouts and original-source authority. Store alone does not replace the
standalone PasteboardEmscripten link owner.

Physical/editor use the common UI main/Bridge overlay and exactly one matching
key root. Pixel1795 keeps its three base main/Bridge/binding sources and original
imports/projection/profile unchanged. Historical capsule maps remain original;
new import origins record exact released postimages and nested predecessor rows.
The five new logical engine CPPs have no preimage in original R099 projection,
while original supplier CPP hashes remain explicit independent authority.

There is one process-lifetime UI/clipboard owner. Normal document/service
invalidation retires document authority; facade/driver close does not promise a
synchronous clipboard reset or rebind. No host OS clipboard or backend-specific
application feature implementation is selected here.

These source changes include the bounded-public-text and stable Begin-selection
Publisher successors. None of the new CPPs has actual WebCore compilation/link
or runtime evidence yet. A new R/S, exact16-context editor reuse proof and
independent reuse root must precede a separate admitted selected-engine plan.
Source preparation never invokes SDK programs and missing retained inputs never
authorize a full engine or kernel fallback.
